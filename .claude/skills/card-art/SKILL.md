# Card art

Martin agrees each card's True Name in chat, then only judges finished pictures on a review page. Everything between is yours: brief, prompts, generation, checks, page, install, learning. His attention is the scarce resource, and Claude tokens are the next one (agents share his subscription; the codex quota is for pictures only, never checks) (the Savanna commons cost ~22 minutes and 14 pictures per card); every step below exists to spend less of it.

An agent that opens pictures gets at most ~25 of them. Past that, older pictures drop out of its context, it reopens them, and every call rewrites its whole cache: on 2026-10-09 one Sonnet agent given 78 pictures looped for three and a half hours and spent ~89% of a five-hour limit. A background agent that looks dead is stopped (TaskStop) before it is replaced, and "no agents are running" is said only after checking.

Everything lives in the design repo `~/Work/fun/animal-kingdom-design/` (`D` below), except the game's art files. Read before starting: `D/cards/art-principles.md` (what the art must do; the only principles doc), `D/cards/true-names.md`, and `python3 D/cards/bar/art.py status` (where every card stands).

Tools, all in `D/cards/bar/`: `art.py` (every step; run it with no arguments for its commands), `gen2.sh` (the generator: Luna passes the prompt to the image model character for character), `manifest.jsonl` (every attempt, review and pick, tracked), `prompts.md` (the prompt writer's rules, the frozen style block, the "what wins" statistics), `review.html` (the review page template), `install.sh`, `edit.sh` (a surface fix on a finished painting only, never composition). Generated pictures land in `bar/r1/<id>.png` with the prompt log beside them.

## A batch, end to end

A batch is one habitat and one rarity (commons first, then rares, then legendaries), named `<habitat>-<rarity>-<n>` (`savanna-common-2`).

1. **True Names.** Every card in the batch needs a line in `true-names.md`. Missing ones: propose one line per card in chat, following that file's rules, and get Martin's agreement before any picture. Write them in, commit.
2. **The habitat block.** `art-principles.md` needs a "<Habitat> <rarity>" line under "The prompt blocks" (`art.py gen` refuses without it). A new one: draft it from the habitat's description, agree it with Martin, then test the look on 3-4 pictures (one per card) before generating the batch.
3. **Prompts, by a cold subagent.** Spawn one fresh agent per batch (Agent tool, `model: "opus"`: this is the creative step) with: the batch name, the card ids, the jobs file path to write (`D/cards/bar/jobs/<batch>-<round>.jsonl`), how many ideas per card (4, one picture each), and the instruction to read `D/cards/art-principles.md` and `D/cards/bar/prompts.md` and follow them. Pass nothing else from this session: no old prompts, no pictures, no summary of past rounds beyond what `art.py status` prints. Never write prompts yourself. The same writer stays on the batch: for every later round, resume it (SendMessage) with Martin's verdicts and notes, so his reactions land on its own reasoning. When the batch is done, its last job is to write what it learned into `prompts.md`; the next batch starts a fresh writer from those files.
4. **Generate.** `python3 D/cards/bar/art.py gen <jobs file> -p 4` in the background. Each picture is ~1-2 minutes; it prints `done <id>` or `FAIL <id>`, and warns if a prompt reached the model altered (`NOT VERBATIM`: stop and fix the proxy). The ChatGPT image quota is its own cap (about 40-50 pictures, then hours of lockout; a FAIL says when it resets): budget a round before starting it.
5. **No gates.** Every generated picture goes on the page: Martin judges a picture in seconds, a Claude checker costs ~14k tokens a picture (2026-10-09: 78 pictures gated for ~1.1M Sonnet tokens, and he had caught the missing leg the checker missed). Nothing filters what he sees; the only check is on the pick, at install.
6. **Review page.** `art.py page <batch>-r<round> <ids...>` with every picture of the round builds `results/card-art/<review>/index.html` in the game repo and its `files.json`. Publish it with the Artifact tool: `file_path` that index.html, `files` from files.json, and the `url` of the card-art review artifact (its link is in `D/cards/notes.md`; publishing to it keeps the page's database). Small batches: four to six cards a page. Send Martin the link and stop; no pick of yours, no captions about flaws.
7. **Verdicts.** When Martin says he has submitted: `ArtifactData` `list` of collection `verdicts` on the page's url, save the result as JSON, `art.py verdicts <review> <file>`. It prints each card's pick and note. A note is a feeling put into words: translate it, don't execute it literally.
8. **Install** each pick. First look at the pick's anatomy yourself: crop its legs and every place two animals touch (`art.py crop <id> x0 y0 x1 y1`), count legs, heads, horns; a flaw goes to Martin in one line before installing (he may still want it, or a surface fix by `edit.sh`). Then `D/cards/bar/install.sh <card_id> <candidate_id>`: the master into `D/cards/<card>.png|jpg`, the game's `static/art/<card>.jpg` and `.webp`, the pick into the manifest, and a first guess at `CROP`/`STRIP`/`FULL` in `static/art.js`. Check the guess against the picture (the head in the portrait, the animal in the card window), correct it, then run the web fast suite (`cd animal_kingdom/web/test && node --test`) in the background. Commit both repos by explicit paths: design repo `cards/<card>.png cards/<card>.jpg cards/bar/manifest.jsonl`, game repo `animal_kingdom/web/static/art/<card>.jpg animal_kingdom/web/static/art/<card>.webp animal_kingdom/web/static/art.js`. A card picked "none" goes back to the batch's writer with its notes.
9. **Learn**, after each review round: `art.py stats` refreshes "What wins" in `prompts.md`. Then, every few rounds rather than every round, spawn a fresh Sonnet agent with the verdicts (`art.py status <batch>`), the stats, and `prompts.md`, `art-principles.md`, asking what in the notes and tags is a rule the writer should have followed. Apply its changes to `prompts.md` yourself when they hold up (commit them); a change to the frozen style block or to `art-principles.md` goes to Martin in chat as a proposal first. Rules are written as current state, one paragraph per line.

## Experiments

A job's `arm` labels an experiment (references: swatch only, swatch plus a rotated settled painting, none) and `raw: true` sends an old prompt unchanged. Arms are never shown to Martin; the manifest holds them, and `art.py status` / the stats compare them after his verdicts. Brushwork swatches come from approved masters: `art.py swatch <card> x0 y0 x1 y1 <name>` (fur, grass, sky, texture only).
