# Card art

Martin agrees each card's True Name in chat, then only judges finished pictures on a review page. Everything between is yours: brief, prompts, generation, checks, page, install, learning. His attention is the scarce resource, and Claude tokens are the next one (agents share his subscription; the codex quota is for pictures only, never checks) (the Savanna commons cost ~22 minutes and 14 pictures per card); every step below exists to spend less of it.

Everything lives in the design repo `~/Work/fun/animal-kingdom-design/` (`D` below), except the game's art files. Read before starting: `D/cards/art-principles.md` (what the art must do; the only principles doc), `D/cards/true-names.md`, and `python3 D/cards/bar/art.py status` (where every card stands).

Tools, all in `D/cards/bar/`: `art.py` (every step; run it with no arguments for its commands), `gen2.sh` (the generator: Luna passes the prompt to the image model character for character), `manifest.jsonl` (every attempt, gate result, review and pick, tracked), `prompts.md` (the prompt writer's rules, the frozen style block, the "what wins" statistics), `gates.md` (the two Sonnet checkers' briefs), `review.html` (the review page template), `install.sh`, `edit.sh` (a surface fix on a finished painting only, never composition). Generated pictures land in `bar/r1/<id>.png` with the prompt log beside them.

## A batch, end to end

A batch is one habitat and one rarity (commons first, then rares, then legendaries), named `<habitat>-<rarity>-<n>` (`savanna-common-2`).

1. **True Names.** Every card in the batch needs a line in `true-names.md`. Missing ones: propose one line per card in chat, following that file's rules, and get Martin's agreement before any picture. Write them in, commit.
2. **The habitat block.** `art-principles.md` needs a "<Habitat> <rarity>" line under "The prompt blocks" (`art.py gen` refuses without it). A new one: draft it from the habitat's description, agree it with Martin, then test the look on 3-4 pictures (one per card) before generating the batch.
3. **Prompts, by a cold subagent.** Spawn one fresh agent per batch (Agent tool, `model: "opus"`: this is the creative step) with: the batch name, the card ids, the jobs file path to write (`D/cards/bar/jobs/<batch>-<round>.jsonl`), how many ideas per card (4-5 on a card's first round; fewer later), and the instruction to read `D/cards/art-principles.md` and `D/cards/bar/prompts.md` and follow them. Pass nothing else from this session: no old prompts, no pictures, no summary of past rounds beyond what `art.py status` prints. Never write prompts yourself.
4. **Generate.** `python3 D/cards/bar/art.py gen <jobs file> -p 4` in the background. Each picture is ~1-2 minutes; it prints `done <id>` or `FAIL <id>`, and warns if a prompt reached the model altered (`NOT VERBATIM`: stop and fix the proxy). The ChatGPT image quota is its own cap (about 40-50 pictures, then hours of lockout; a FAIL says when it resets): budget a round before starting it.
5. **Gates** (`gates.md`; nothing reaches Martin before them):
   1. `art.py blind <ids>` prints a folder of anonymised copies. Spawn the blind reader (Agent tool, `model: "haiku"`: a few words per picture needs no judgement) with the "blind reader" section of `gates.md` and that folder only.
   2. `art.py readings <folder>` stores and prints the readings by id.
   3. Spawn the checker (`model: "sonnet"`) with the "checker" section, the ids, the printed readings and a results path (`D/cards/bar/gate/<batch>-<round>.json`). Split more than ~12 pictures across checkers.
   4. `art.py gate <results>` merges and prints who passed.
   5. Failures: re-roll the same idea in fresh wording (a cold writer, given the failed ideas' labels only, never the flaw). Repeat until four distinct ideas pass per card. A card at its third round changes ideas; a stuck card gets a fresh writer.
6. **Review page.** Pick four passing pictures per card, each a different idea, distinct from each other and from the live art at thumbnail size (`gates.md` §3). `art.py page <batch>-r<round> <ids...>` builds `results/card-art/<review>/index.html` in the game repo and its `files.json`. Publish it with the Artifact tool: `file_path` that index.html, `files` from files.json, `capabilities: {"db": {}}`, and the `url` of the card-art review artifact when one exists (one reusable page; its link is in `D/cards/notes.md`, record it there on first publish). Small batches: four to six cards a page. Send Martin the link and stop; no pick of yours, no captions about flaws.
7. **Verdicts.** When Martin says he has submitted: `ArtifactData` `list` of collection `verdicts` on the page's url, save the result as JSON, `art.py verdicts <review> <file>`. It prints each card's pick and note. A note is a feeling put into words: translate it, don't execute it literally.
8. **Install** each pick: `D/cards/bar/install.sh <card_id> <candidate_id>`: the master into `D/cards/<card>.png|jpg`, the game's `static/art/<card>.jpg` and `.webp`, the pick into the manifest, and a first guess at `CROP`/`STRIP`/`FULL` in `static/art.js`. Check the guess against the picture (the head in the portrait, the animal in the card window), correct it, then run the web fast suite (`cd animal_kingdom/web/test && node --test`) in the background. Commit both repos by explicit paths: design repo `cards/<card>.png cards/<card>.jpg cards/bar/manifest.jsonl`, game repo `animal_kingdom/web/static/art/<card>.jpg animal_kingdom/web/static/art/<card>.webp animal_kingdom/web/static/art.js`. A card picked "none" goes back to step 3 with its notes.
9. **Learn**, after each review round: `art.py stats` refreshes "What wins" in `prompts.md`. Then spawn a fresh Sonnet agent with the round's verdicts (`art.py status <batch>`), the stats, and `prompts.md`, `gates.md`, `art-principles.md`, asking what in the notes and tags is a rule the writer or the checkers should have followed. Apply its changes to `prompts.md` and `gates.md` yourself when they hold up (commit them); a change to the frozen style block or to `art-principles.md` goes to Martin in chat as a proposal first. Rules are written as current state, one paragraph per line.

## Experiments

A job's `arm` labels an experiment (references: swatch only, swatch plus a rotated settled painting, none) and `raw: true` sends an old prompt unchanged. Arms are never shown to Martin; the manifest holds them, and `art.py status` / the stats compare them after his verdicts. Brushwork swatches come from approved masters: `art.py swatch <card> x0 y0 x1 y1 <name>` (fur, grass, sky, texture only).
